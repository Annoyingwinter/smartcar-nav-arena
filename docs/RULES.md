### 2.1 控制线下线评分细则

| 任务 | 分值 |
|---|---|
| 安装 ubuntu + ROS | 20 分 |
| 建图 | 5 分 |
| 自主导航任务 | 25 分 |

**自主导航 25 分构成:**

| 项 | 得分细则 |
|---|---|
| 成功发车 | 5 分(小车离开起点区域) |
| 成功到达终点区域 | 10 分 |
| 时间得分 | 5/3 分(带锥桶最高五分,不带锥桶最高 3 分) |
| 选择带锥桶的地图 | 5 分 |
| 碰撞 | 每次扣 2 分(上限 5 分) |
| 停车:小车一轮在白线外 | 扣 2 分 |
| 停车:小车两轮在白线外 | 扣 5 分 |
| 停车:小车三轮在白线外 | 扣 8 分 |
| 停车:四个轮全在白线外 | 未完成比赛,扣 10 分,不参与时间排名 |

### 2.2 细则注(决定排名怎么算,照抄)

> 1. 本次比赛时间相同者记为同名次,时间得分以名次数量(不是参赛队伍数量)分级,并按照排名均匀等
>    级赋分,末位 0 分,首位 6 分。若本次比赛无完赛队伍,则均以 0 分计分。小车无法自动导航的组别,
>    时间得分记为 0 分。
> 2. 时间得分方面,选择带锥桶的队伍为一组共同排名,最高五分;选择不带锥桶的队伍为一组共同排名,
>    最高三分。
> 3. **碰撞只考虑与锥桶的碰撞,碰撞墙体不扣分。**
> 4. 最终计算一轮分站赛排名时,总分数相同的队伍按比赛完成时间倒序排名。
> 5. **使用非给定控制地图建图者,时间得分记为 0 分,到达终点区域的得分记为 0 分。**
> 6. 禁止修改小车模型代码等影响赛事公平的行为。(见第 1 节)
> 7. 如比赛细则还存在不完善的地方,欢迎大家向我们反映。有关比赛规则与评分细则,组委会保留解释权利。

### 2.3 障碍物(锥桶)规则

> 「障碍物为图示红白相间的锥桶,随机摆放至起点到终点的路途中(保证最小通过距离不小于小车宽度),
> 且锥桶的数量不小于 3 个,比赛时每队障碍物摆放位置一样,每队有三次尝试机会。」

落地:

- 锥桶由 `harness/spawn_cones.py` 按种子生成,**必须 ≥3 个**,且生成器会校验每处摆放的
  通过空间(默认 ≥0.5m,可用 `--gap` 调低,但那是你的选择,榜单必须记录)。
- 「每队障碍物摆放位置一样」→ 标准配置固定为 **B1 = seed 42**、**B2 = seed 7**。
  想跟别人比,就必须用这两个种子之一,或用别人的种子并在备注附 `--dry-run` 输出。

## 3. 本榜单的排名计分制

细则的"时间得分"依赖现场参赛队伍数量,本仓库是**异步打榜**,队伍数会变,所以
把它落成一条可复算的规则。**导航小计完全按细则算,时间分是本榜单附加的排序维度。**

```
导航小计 = 成功发车 5
         + 到达终点区域 10
         + 选择带锥桶地图 5
         - 碰撞罚 (2/次, 上限 5)
         - 白线外停车罚 (按细则)
         = 0 ~ 20
```

> 注:细则里"建图 5 分"是现场分站赛项目,打榜不计;但**注 5**规定用非给定地图建图者
> 到达终点区域也记 0 分 —— 本仓库只接受给定基准图,故不涉及。

**分组**:无锥组(用 `benchmark_map.pgm`,不摆锥)与带锥组(摆锥)分别排名,
时间分上限分别是 3 与 5(细则注 2)。

**时间分**:组内**完赛**队伍按仿真用时升序排名,均匀赋分:

- 设该组完赛队伍数为 `n`,时间分上限为 `cap`(无锥 3 / 带锥 5);
- 第 `i` 名(1 ≤ i ≤ n)的时间分 = `cap * (n - i) / (n - 1)`;
  等价说法:从 `cap` 均匀递减到 `0`,共 `n - 1` 档。
  例:`n=2, cap=3` → `3, 0`;`n=3, cap=3` → `3, 1.5, 0`;
  `n=3, cap=5` → `5, 2.5, 0`;
- `n == 1` 时唯一完赛队得 `cap`(公式退化,特判);
- 该组无完赛队伍,则所有队伍时间分 0(细则注 1);
- DNF(未完赛/超时)队伍**不参与**该组时间排名,时间分 0;
- 同一用时并列同名次(细则注 1),并列队伍取该名次区间的**平均**分。

**模型总分 = 两组时间分之和**,模型在每组只取自己**最好的一行**(同分取用时更短的)。

## 5. 计时口径

- **一切以 `/clock` 仿真秒为准**,与渲染速度无关。RTF≈0.1(软渲染)与 RTF≈1.0(GPU)出的成绩可直接比较。
- 墙钟时间只写进日志供调试,不计分。
- 「每队有三次尝试机会」:本榜单把一轮视为**一次尝试**,由 commander 自己决定何时放弃
  (重试/换偏置/跳航点都在算法内部完成)。一条成绩行 = 一次发车到结束(或超时)。

---

## 6. 碰撞口径

- **只算与锥桶的碰撞,碰墙不扣分**(细则注 3)。
- 本榜单的判定是**代理估算**:车中心与锥桶中心距离 `< 0.30 m` 记一次事件,连续接触去重
  (同一次接触只记一次,离开 0.30 m 半径后再接触才算新事件)。
- 这个口径**不是裁判目判**,已在 `docs/leaderboard.json` 里标注。同一算法不同实现可能有偏差,
  因此维护者复跑(见 [SUBMISSION.md](SUBMISSION.md))时会核对碰撞数是否落在合理量级。

## 7. 纪元与成绩行归属(维护者的设计决定)

榜单里已有的 8 条成绩行是在**交接前的私有工作空间**上跑的。那套工作空间的
`move_base`/`AMCL` 参数被前两代模型调过(`update_min_d 0.05`、`laser_max_beams 360`、
`xy_goal_tolerance 0.35`、local/global costmap 频率下调、global_costmap 加了
`obstacle_layer`),而本仓库的公共基线**不是**这套参数 —— 见 [CONFIG_PROVENANCE.md](CONFIG_PROVENANCE.md)。

把两者混在一张榜里排名是不诚实的:新来的挑战者按公共基线调参,却要和在另一套参数下
跑出来的数字比时间。所以榜单分两个纪元:

| 纪元 | 状态 | 内容 | 可比性 |
|---|---|---|---|
| **纪元 A** `legacy-2026-10` | 参考行 | 交接前私有配置上跑出的全部 8 行(GLM-5.3 v1/v3、Space Bunny Free v2) | 仅纪元 A 内部可比 |
| **纪元 B** `public-baseline` | **正式榜** | 在本仓库公共基线上跑出的新行 | 所有纪元 B 的行互相可比 |

### 规则

1. **时间分只在同一纪元、同一组内排序。** 纪元 A 的 67.6 s 不与纪元 B 的任何数字比较。
2. **纪元 A 冻结**,不再追加新行。它是历史档案,不是可刷的榜。
3. **纪元 B 是唯一的正式榜。** 新挑战者在这里打新行。
4. 每条成绩行必须声明 `epoch`,并附该纪元下生效的 commander SHA 与 nav yaml SHA。
5. **不追溯、不改写纪元 A 的数字。** 唯一的例外是纯算术口径的公开化:前代榜单按当时的
   临时口径("两队时冠军=上限、亚军=0")给 Space Bunny Free 无锥组时间分 0;本榜按第 3 节
   已公布的均匀赋分规则重算得 **1.5**。这是唯一一处分歧,方向对该行有利,因此在
   `leaderboard.json` 的 `deviation_note` 里公开列明,并在前代榜单原值旁边保留
   `as_published_by_predecessor` 供核对。

### 邀请前代维护者在新基线复跑

**这是解决纪元差异的根本办法,优先于任何口径讨论。** 前代维护者(GLM-5.3)持有
`commander v1`(SHA `6fe82777`),该版本在 `xy_goal_tolerance 0.22` 下跑出过 67.6 s 的无锥成绩,
而 0.22 **正是本仓库公共基线的取值**;差异只在 `update_min_d`/`laser_max_beams`/
costmap 频率等几项。因此 v1 在纪元 B 上大概率可直接复现甚至更快。
我们已向其发出复跑邀请;若 v1 在纪元 B 复跑出成绩,该行以纪元 B 的身份入榜,
**纪元 A 的对应行不删除**(历史档案),榜单会并排显示两者。

任何人也可以自己复跑任何纪元 A 的行 —— commander 源码由该行作者按
[SUBMISSION.md](SUBMISSION.md) 第 2 节提供,复跑结果作为**新行**入纪元 B,
`reproduced_from` 字段指回原行。
