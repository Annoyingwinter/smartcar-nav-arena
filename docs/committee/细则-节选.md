## 二、任务要求 · 控制

> ### 控制总体任务
>
> ROS 组控制任务主要有两个方面：
>
> 1. 基于 Navigation 系列功能包实现小车从起点到终点的自主导航，能应对障碍物和路径规划问题，保证小车运动稳定、避障合理，并在规定规则下完成比赛考核；
> 2. 熟悉 ROS 话题、服务、参数服务器的通信机制，可以编写简单的功能包实现简单的状态机决策驱动小车完成比赛任务；
> 3. 机械臂相关抓取任务，通过控制各个 joint 转角控制末端空间位姿。

## 二、任务要求 · 障碍物

> 障碍物为图示红白相间的锥桶，随机摆放至起点到终点的路途中（保证最小通过距离不小于小车宽度），
> 且锥桶的数量不小于 3 个，比赛时每队障碍物摆放位置一样，每队有三次尝试机会。

## 三、评分细则 · 注

> 1. 本次比赛时间相同者记为同名次，时间得分以名次数量（不是参赛队伍数量）分级，
>    并按照排名均匀等级赋分，末位 0 分，首位 6 分。若本次比赛无完赛队伍，则均以 0 分计分。
>    小车无法自动导航的组别，时间得分记为 0 分。
> 2. 时间得分方面，选择带锥桶的队伍为一组共同排名，最高五分；
>    选择不带锥桶的队伍为一组共同排名，最高三分。
> 3. **碰撞只考虑与锥桶的碰撞，碰撞墙体不扣分。**
> 4. 最终计算一轮分站赛排名时，总分数相同的队伍按比赛完成时间倒序排名。
> 5. **使用非给定控制地图建图者，时间得分记为 0 分，到达终点区域的得分记为 0 分。**
> 6. **禁止修改小车模型代码等影响赛事公平的行为。在每组比赛前，会有对计时器代码和小车模型代码的代码检测，
>    如有发现，组委会将取消对应组别比赛资格！**
> 7. 如比赛细则还存在不完善的地方，欢迎大家向我们反映。有关比赛规则与评分细则，组委会保留解释权利。

## 四、得分体系

> 三次比赛分数分配：ROS 组拟定开展三次比赛。第一次分站赛成绩占比 10%，
> 第二次分站赛成绩占比 30%，第三次分站赛（决赛）占比 60%。所有比赛结束后，
> 按照加权的形式计算各个队伍最终得分，并进行排名与颁奖。

## 本仓库对上述条文的落地对照

| 细则条文 | 本仓库落地 |
|---|---|
| 注 6：小车模型/计时器代码检测 | 红线文件见 `docs/RULES.md` 第 1 节；`bash harness/verify_redline.sh` 一键核对 |
| 注 3：碰撞只算锥桶 | `harness/bench_monitor.py` 只统计锥桶距离；碰墙不扣分 |
| 注 2：带锥/不带锥分组排名 | 两个组分别排名，时间分上限 5 / 3，见 `docs/RULES.md` 第 3 节 |
| 注 1：末位 0 分、无完赛则全组 0 | `time_score` 公式；`harness/validate_leaderboard.py` 会重算核对 |
| 注 5：非给定地图到达终点记 0 | 本仓库只接受 `env/benchmark_map.pgm`，不涉及 |
| 「每队三次尝试机会」 | 一轮 = 一次尝试，见 `docs/BENCHMARK.md` 第 4.3 节 |
| 「锥桶数量不小于 3 个」 | `harness/spawn_cones.py` 固定生成 3 个并校验通过空间 |
| 「每队障碍物摆放位置一样」 | 标准配置 B1 = seed 42、B2 = seed 7 |
| 「停车白线外」扣分 | 自动计分取最轻一档（一轮 −2）并标注为估算，见 `docs/BENCHMARK.md` |

> ⚠️ **注意"首位 6 分"与"最高五分/三分"的关系。** 细则注 1 写"首位 6 分"是通用表述，
> 注 2 把它分组后封顶为 5（带锥）/ 3（不带锥）。本榜单按注 2 的封顶执行。
